\section{Modelling Pipeline}
All models use one shared pipeline structure. This is important because a model comparison is only meaningful when models receive the same rows, target, split, preprocessing rules, and metrics. The repository therefore separates common utilities from model-specific scripts.

\subsection{Chronological Split}
A random split would mix past and future observations. This would make the task easier than real forecasting and could hide temporal drift. The final split is therefore chronological: 70\% training, 15\% validation, and 15\% test. The validation set is used for development decisions and hyperparameter tuning. The test set is used only for final reporting.

\section{Model Selection Strategy}
The model set was chosen to cover increasing complexity and different learning principles taught or discussed in the course: baseline modelling, linear regression, regularization, local neighbourhood methods, decision trees, bagging, boosting, and a nonlinear neural reference. This is more informative than testing many similar variants of one algorithm.

\subsection{Overfitting Logic}
The model comparison also serves as an overfitting diagnosis. Linear models are expected to be stable but may underfit. KNN and single trees can memorize local patterns and therefore risk high variance. Random Forest combats variance through bagging. Gradient Boosting can reduce bias, but must be tuned carefully because too many or too deep trees can overfit. This is why every model is evaluated on train, validation, and test data and why the final choice is not based on training error.
